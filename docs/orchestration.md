# Orchestration Model

## Overview
The OpenCode framework now uses a **task‑registry** to coordinate the lifecycle of sub‑agents. Each core agent registers a task, emits a heartbeat, and updates its status (`pending → running → done` or `error`). The **tech‑lead** (router) and **agent‑supervisor** rely on this registry to know when a child has truly finished, eliminating the previous dead‑lock where the tech‑lead waited on a process that had already exited.

## Task Registry (`$HOME/.config/opencode/tasks.json`)
```json
{
  "tasks": [
    {
      "id": "<UUID>",
      "agent": "developer",
      "status": "pending|running|done|error",
      "pid": <PID|null>,
      "created": <epoch>,
      "updated": <epoch>
    }
  ]
}
```
* **`id`** – UUID generated by `add_task.sh`.
* **`agent`** – Name of the agent (matches the `name:` front‑matter).
* **`status`** – Current lifecycle state.
* **`pid`** – PID of the heartbeat process (used for cleanup).
* **`created` / `updated`** – Timestamps for auditing.

## Heartbeat (`$HOME/.config/opencode/heartbeats/heartbeat.<agent>`)
Each agent starts `heartbeat.sh <agent>` in the background. The script writes the current epoch timestamp every **5 seconds**. The monitor process (`monitor_tasks.sh`) checks these files every **10 seconds**. If a heartbeat is older than **30 seconds**, the monitor kills the stored PID (if any) and marks the task as `error`.

## Locks
* **`sync.lock`** – Protects `sync‑agents‑global.sh` from concurrent runs.
* **`verify.lock`** – Protects `verify‑agents.sh`.
* **`tasks.lock`** – Guarantees atomic updates to `tasks.json`.

## Agent Boilerplate (to be included in each core agent)
```bash
# Register task
TASK_ID=$(bash .opencode/scripts/add_task.sh <agent>)
# Start heartbeat
bash .opencode/scripts/heartbeat.sh <agent> &
HB_PID=$!
# Mark running
bash .opencode/scripts/update_task.sh "$TASK_ID" "{\"status\":\"running\",\"pid\":$HB_PID}"
# ... agent's normal work (read/write/edit/bash) ...
# On success
bash .opencode/scripts/update_task.sh "$TASK_ID" "{\"status\":\"done\",\"pid\":null}"
# Cleanup heartbeat
kill $HB_PID 2>/dev/null || true
```
Replace `<agent>` with the agent’s name (e.g., `developer`).

## Supervisor Monitoring
The **agent‑supervisor** should start the monitor once per session (see the note added to `agent-supervisor.md`):
```bash
~/.opencode/scripts/monitor_tasks.sh &
```
The monitor runs in the background for the lifetime of the session, ensuring any truly stalled tasks are cleaned up.

## Testing
* **Unit tests** (`tests/task_registry.test.sh`) verify `add_task.sh`, `update_task.sh`, `read_task.sh`, and the monitor’s stale‑heartbeat handling.
* **Integration test** (`tests/integration_dummy.test.sh`) uses a minimal `dummy-agent` that follows the boilerplate, sleeps 2 seconds, and marks itself `done`. The test asserts the task transitions `pending → running → done` without the tech‑lead hanging.

## Adding New Agents
1. Include the boilerplate code block in the agent’s markdown.
2. Ensure the agent’s `tools:` list contains `bash: true` (required for the helper scripts).
3. The tech‑lead will automatically route to the new agent; the monitor will handle its lifecycle.
