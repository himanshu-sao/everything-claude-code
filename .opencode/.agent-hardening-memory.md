# 🧠 Agent Hardening Protocol & Memory (April 2026)

## The Core Problem: "Ghost Coding" & Silent Stalls
We experienced a systemic failure in the OpenCode multi-agent ecosystem where agents would fail silently or "ghost code." 
- **Stalling:** Agents (like `qa-engineer` or `ui-engineer`) lacked context or required tools/keys, but did not have instructions to pause and ask the user. They simply halted or entered loops.
- **Ghost Coding:** Agents (like `tech-lead` and `developer`) were delegating tasks and hallucinating successful completion without actually modifying the filesystem using the `write` or `edit` tools.

## The Solution: "Smart Pause" & "Persistent Output"
To achieve production-grade reliability, we implemented a unified protocol across the entire agent fleet.

### 1. The `BLOCK:` Protocol (Smart Pause)
If an agent is missing context, environment variables, API keys, or permissions to proceed, it must STOP and return a message starting with **"BLOCK: [Reason]"**. 
*Why?* This immediately returns control to the user to provide the missing pieces, preventing endless loops or hallucinated successes.

### 2. The Persistent Output Mandate
All code-writing agents MUST verify that they have used the `write` or `edit` tool to alter the filesystem before signing off. 
*Why?* To ensure verifiable progress and completely eliminate "Ghost Coding."

### 3. Audit Verification
All Reviewer agents (`code-reviewer`, `security-reviewer`, `database-reviewer`) MUST use the `read` tool to explicitly audit the file contents.
*Why?* Prevents reviewers from hallucinating "LGTM" (Looks Good To Me) based solely on filenames.
